# Music player

Music is the first control in the Friends & Fables website header, before the existing background and grouping controls. Expanding this header control group provides **Previous**, **Play/Pause**, **Next**, **Volume**, and **Music library**. The library opens the full music panel, whose player also provides Stop, seeking, mute, and repeat. Collapse the header controls without interrupting playback or changing the open library. The player follows the app's appearance and English/Russian interface setting. These controls describe current source; the published 0.7.2.7 release predates the UI correction that moved Music to the first header position.

Add a track name and a direct HTTPS audio link. MP3, OGG, WAV, and other formats supported by the included Chromium runtime can play. YouTube and Spotify page links are not audio files. Links must remain accessible; expiring download links will eventually stop working.

The built-in **Music catalog** contains 266 tracks from [Scott Buckley's official Creative Commons library](https://www.scottbuckley.com.au/library/). Search by title, artist, mood, genre, or instrument in English or Russian; use the mood and genre filters to narrow results. Common scene keywords such as battle, dungeon, tavern, and their Russian equivalents also work. **Add to playlist** saves a track without starting audio; **Play** saves and starts it. Adding the same track again reuses the existing entry. The catalog is separate from the 50-track saved playlist.

Each entry includes the artist, license, and buttons for its official source and license pages. **Copy attribution** copies the selected catalog track's title, artist, source URL, and license URL. These tracks are offered under [CC BY 4.0](https://www.scottbuckley.com.au/library/using-this-music/); include credit when using them in published recordings. The metadata and all 266 direct audio URLs were checked on 2026-10-01. This is a bundled snapshot: browsing/search needs no music API or account, and audio is fetched from the artist only when playback starts. Links can change later.

The player provides Play/Pause, Stop, Previous/Next, seeking, volume, mute, and repeat for the current track. The playlist advances when a track ends; repeat keeps the current track playing. Selecting a track starts it. Previous/Next preserve paused playback.

Up to 50 tracks, the selected track, volume, mute, and repeat are saved in the app profile's `music.json`, separate from portable appearance themes. The player starts paused when the app launches and makes no audio request until Play. Campaign reloads and hiding the music library do not interrupt playback. Closing the main app window stops playback. The expanded website-header group provides previous, play/pause, next, volume, and library access. The full library panel provides stop, seeking, mute, and repeat in addition to transport controls. The controls use outlined icons, support keyboard input, and respect reduced motion. Volume and mute remain part of the existing saved music preferences.

The **Music folders** tab lets you choose folders containing downloaded MP3, OGG, WAV, FLAC, M4A, OPUS, AAC, or WEBM files, subject to Chromium format support. Search by title or relative path, choose a folder filter, then play or add tracks to the playlist. Up to 16 folders and 1,000 tracks per folder are indexed through eight nested levels. Refresh to discover new files. Removing a source does not delete music. Local playback uses app URLs mapped only to chosen folders, with symlinks and outside paths excluded; these links cannot be shared as public audio URLs. Sources persist in `music-folders.json`.

**Copy track link** copies the selected audio URL for sharing. This first player plays audio locally; it does not synchronize playback or control other campaign members' players. No campaign message is sent automatically.

The player runs in a persistent sandboxed main-window view and its own browser session. Only that view can read/save music preferences or copy a saved link. The app-owned toolbar has a restricted transport API. The website remains sandboxed without a preload or general application IPC API. The desktop adds its header shortcut and transport controls through a narrowly validated custom-URL command route; only the active registered campaign webContents main frame and its own initiator frame, an allowed command/value, and the current private document token are accepted. Audio links load as media, with no remote scripts or embedded website players.

For focused music validation, run `npm run build` once after changing source, then `node --test tests/music/music-settings.test.cjs` and `npm run test:music`; these cover offline WAV playback, seeking, mute/volume/repeat, saved playlists, header control placement, theme/localization changes, and access restrictions. The full `npm test` command already builds through `pretest`, so it needs no separate build.

Music is placed first in the website header; it does not replace the desktop toolbar controls. The Music Settings section in the unified Settings hub remains reserved; existing global music preferences already save volume, mute, repeat, selected track, and playlist in `music.json`. Playback starts paused. No new Music preference controls are described here.

On Hyprland, the main window’s Minimize action hides it to a tray icon. Click the icon or choose Show app to restore the same window; playback and drafts stay intact. The tray menu also has Exit app. Other desktops retain native minimization.
